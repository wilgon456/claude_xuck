# 한국어 윤문

사용자가 준 한국어 글을 **짧고 평범한 문장**으로 다시 쓴다. 뜻은 바꾸지 않는다.

## 먼저 확인할 것

글을 받으면 **누가 읽는 글인지** 한 줄로 묻는다. 답에 따라 다듬는 방향이 달라진다.

- 사내 슬랙·메일 → 짧게, 결론 먼저, 존댓말은 원문 유지
- 발주처·고객 제출 문서 → 격식은 지키되 군더더기만 걷어낸다
- 공지·안내문 → 지시를 앞에, 배경을 뒤에
- 이미 명확하면 묻지 말고 바로 다듬는다(짧은 문장 몇 개짜리 글)

## 다듬는 기준

[references/rules.ko.md](../../references/rules.ko.md)의 열한 개 규칙을 그대로 쓴다. 글에서 특히
이 여섯 가지를 찾는다. 위에 있는 것이 더 자주 나오고 더 크게 걸린다.

1. **어려운 개념을 이름만 대고 넘어간 것** — 그 이름을 모르는 사람에게 무슨 일이 벌어지는지로
   바꿔 쓴다. 이름을 남겨야 하면 **풀어 쓴 다음 괄호**에 넣는다.
   - 「멱등성을 보장합니다」 → 「두 번 눌러도 한 번만 처리됩니다」
   - 「캐시를 무효화합니다」 → 「저장해 둔 것을 버려서 다음에 새로 가져옵니다」
   - 「비동기로 처리합니다」 → 「기다리지 않고 넘어가고, 끝나면 알려 줍니다」
2. **공문투** — 사람이 말하듯 바꾼다
   - 「처리 완료되었습니다」 → 「끝났습니다」
   - 「~에 대한 검토를 진행하였습니다」 → 「~을 봤습니다」
   - 「반영이 필요합니다」 → 「고쳐야 합니다」
3. **번역투** — 영어 문장 골격에 한국어 낱말만 끼운 것
   - 「이 부분이 더 아픕니다」 → 「이쪽이 손해가 더 큽니다」
   - 「가시성을 확보해야」 → 「무엇이 어떻게 돌아가는지 볼 수 있어야」
4. **군더더기** — 「~라고 할 수 있습니다」, 「~인 것으로 보입니다」, 「기본적으로」, 「사실상」
   - 「지연이 발생한 것으로 보입니다」 → 「늦어졌습니다」
5. **기계 용어 노출** — 오류 번호·함수 이름·설정값을 설명 없이 쓴 것
   - 「타임아웃이 발생」 → 「기다리다 끊겼습니다」
6. **한 문장에 두세 가지** — 접속사로 이어 붙인 긴 문장은 끊는다

## 내놓는 방식

**고친 글을 먼저 준다.** 설명은 뒤에 붙인다. 사용자가 급할 때 위만 복사해 갈 수 있어야 한다.

````
## 다듬은 글

(여기에 전문. 바로 복사해 쓸 수 있게)

## 무엇을 고쳤나

- 「원문 표현」 → 「고친 표현」 : 왜 고쳤는지 한 줄
- (세 개에서 다섯 개만. 같은 종류는 묶어서 한 줄로)

## 손대지 않은 것

- (사실·숫자·고유명사·존댓말 등급은 그대로 뒀다는 것을 밝힌다)
````

고친 곳이 다섯 개를 넘으면 **가장 많이 나온 문제 세 가지**만 설명한다. 스무 줄짜리 목록은
읽지 않는다.

## 지키는 선

- **사실·숫자·날짜·고유명사·금액을 바꾸지 않는다.** 어색해도 그대로 둔다. 이상하면 고치지 말고
  「이 숫자가 맞는지 확인해 주세요」라고 물어본다.
- **뜻을 줄이지 않는다.** 짧게 만들려고 조건이나 예외를 빼면 안 된다.
- **존댓말 등급을 올리거나 내리지 않는다.** 원문이 「~해요」면 「~합니다」로 바꾸지 않는다.
- **원문에 없는 말을 넣지 않는다.** 근거·수치를 보태지 않는다.
- 사용자가 「짧게만」이라고 하면 설명 부분을 생략하고 고친 글만 준다.

## 짧은 글 한 문장짜리

한 문장만 주면 표도 소제목도 만들지 않는다. 고친 문장 한 줄과 이유 한 줄로 끝낸다.

```
「지연이 발생한 것으로 보입니다」 → 「늦어졌습니다」
「발생한 것으로 보입니다」는 영어 수동태를 옮긴 말입니다.
```
