# claude_xuck

**Claude Code가 한국어를 한국어답게 쓰게 만드는 플러그인**

**어려운 개념을 이름만 대고 넘어가기**를 막습니다.

## 이런 답변을 받고 계신가요

| Claude가 이렇게 말하면 | 이렇게 바뀝니다 | 무엇이 문제였나 |
| --- | --- | --- |
| "멱등성을 보장합니다" | "두 번 눌러도 한 번만 처리됩니다" | 개념 이름만 댔다 |
| "캐시를 무효화합니다" | "저장해 둔 것을 버려서 다음에 새로 가져옵니다" | 개념 이름만 댔다 |
| "이 부분이 더 아픕니다" | "이쪽이 손해가 더 큽니다" | 영어를 옮겼다 |
| "침묵이 정상과 구분되지 않습니다" | "아무 신호가 없어서 잘 돌아가는지 죽었는지 모릅니다" | 영어를 옮겼다 |
| "처리 완료되었습니다" | "끝났습니다" | 공문투 |
| "코드 30이 떴습니다" | "우리 열쇠로는 그 자료가 안 열립니다" | 기계가 뱉은 말 |

**넷은 서로 다른 문제입니다.** 전문용어를 안 써도 문장 골격이 영어면 한국말로 안 들립니다.
공문투는 그것과 또 다릅니다. 그리고 가장 자주 어기는 것은 **어려운 개념을 이름만 대고
넘어가는 것**인데, 낱말 하나라서 눈에 안 걸립니다. 그래서 규칙도 따로 있어야 고쳐집니다.

## 무엇이 들어 있나

### 1. 답변 말투 (자동)

깔면 끝입니다. **시스템 프롬프트가 바뀌고, 대화 중에도 계속 상기됩니다.** 그래서 대화가
길어져도 말투가 다시 망가지지 않습니다.

### 2. 윤문 스킬 (필요할 때)

**내가 쓴 글**을 다듬어 달라고 할 때 씁니다. 보고서, 슬랙 메시지, 메일, 제안서 문구 같은 것.

```
이 문단 좀 다듬어줘

지연이 발생한 것으로 보이며, 관련하여 확인이 필요한 부분이
있어 공유드립니다.
```

고친 글을 먼저 주고 무엇을 왜 고쳤는지 뒤에 붙입니다. **숫자·날짜·고유명사·존댓말은 건드리지
않습니다.** 급하면 위만 복사해 가시면 됩니다.

## 규칙 열한 개

<details>
<summary>펼쳐 보기</summary>

**어떻게 쓰나**

1. **짧게 쓴다** — 다섯 문장 안에 끝낼 수 있는지 먼저 본다
2. **표는 정말 비교할 때만** — 굵은 글씨를 문단마다 넣지 않는다
3. **결론 먼저** — 확인 과정은 물어볼 때만 말한다

**무엇을 쓰지 않나**

4. **어려운 개념을 이름만 대지 않는다** — 무슨 일이 벌어지는지로 바꿔 말한다
5. **기계가 뱉은 말을 옮기지 않는다** — 오류 번호 대신 무슨 일이 생겼는지
6. **공문투로 쓰지 않는다** — "처리 완료되었습니다" → "끝났습니다"
7. **번역투로 쓰지 않는다** — 영어 골격에 한국어 낱말만 끼우지 않는다
8. **없는 말을 지어내지 않는다** — 국어사전에 있는 말을 쓴다
9. **한자·수학·경제 용어를 멋으로 쓰지 않는다**

**지적을 받으면**

10. **한 줄로 인정하고 고친 내용만** — 사과를 늘어놓지 않는다
11. **쓰고 나서 소리 내어 읽어 본다** — 어색하면 영어나 공문을 옮긴 것이다

전문과 예시: [rules.ko.md](plugins/plain-korean-reply/references/rules.ko.md)

</details>

따로 만들거나 검사할 게 없습니다.

## 왜 여기에 두는가

규칙을 어디에 두느냐가 전부입니다. 세 자리를 다 써 보고 정했습니다.

| 자리 | 어떻게 들어가나 |
| --- | --- |
| 스킬 | **불러야** 열립니다. 평소 대화에는 안 들어갑니다 |
| `CLAUDE.md` | 시스템 프롬프트 **뒤에 붙는 사용자 메시지**. 대화가 길어지면 묻힙니다 |
| **출력 스타일** | **시스템 프롬프트를 직접 바꾸고, 대화 중에도 계속 상기시킵니다** |

기억 파일과 `CLAUDE.md`에 적어 두고 같은 지적을 여섯 번 받은 끝에 출력 스타일로 옮겼습니다.
공식 문서에도 이렇게 적혀 있습니다 — "All output styles trigger reminders ... **during the
conversation**."

Claude Code의 기본 개발 지침은 살려 뒀습니다(`keep-coding-instructions`). 말투만 바꾸는 것이고
코드 다루는 방식은 그대로입니다.
